## What was taken, and why the amalgamation

Taken: `distr/flecs.c`, `distr/flecs.h`, `LICENSE` — three files, byte for byte.

flecs publishes two forms of itself: the `src/` tree of ~40 translation units, and the
two-file amalgamation under `distr/` that upstream generates from it and ships as the
supported way to embed the library. The amalgamation is what this package vendors:

- It is one translation unit, so the compiler inlines across the whole library. That is
  a real code-generation advantage over compiling the pieces separately without LTO.
- There is no source list to maintain, and therefore no way for a re-vendor to silently
  change which files compile — the failure mode explicit source lists exist to prevent
  elsewhere simply cannot occur here.
- It is generated by upstream and released with the tag, so it is upstream's artifact,
  not a repackaging decision made here.

`distr/flecs_no_addons.{c,h}` were **not** taken. Addon selection is a compile-time
choice this package exposes as build options (see the README), which covers the same
ground without a second copy of the library on disk.

Everything else upstream ships — `src/`, `include/`, `test/`, `examples/`, `docs/`,
`cmake/`, `meson.build`, the Bazel files — is excluded. None of it is needed to build or
use the library, and `build.zig` supersedes every build system among it.

## Compiling this at `-std=c99`

This package compiles flecs as strict C99. One consequence is worth recording, because
it is not obvious and it only appears on one platform:

**glibc hides POSIX declarations under `-std=c99`.** Strict-conformance mode defines
`__STRICT_ANSI__`, and glibc's headers then expose only ISO C. The `FLECS_HTTP` addon
calls `getnameinfo` and uses `NI_NUMERICHOST`/`NI_NUMERICSERV` from `<netdb.h>`, all of
which are POSIX rather than ISO C, so the build fails with an implicit-declaration error
on glibc targets and nowhere else. musl, macOS and the Windows targets are unaffected.

`build.zig` therefore adds `-D_POSIX_C_SOURCE=200112L` when the target is Linux *and*
the HTTP addon is in the selected set. That is the minimum feature-test macro exposing
`getnameinfo`, and it is applied from the computed addon set, so turning HTTP on later
brings it along automatically.

## Upstream behaviour this package works around

Recorded so a future re-vendor can check whether any of it has been fixed, and so the
workarounds are not mistaken for arbitrary defensiveness.

**The OS API must be given its defaults before it is replaced.** The documented way to
install custom callbacks is `ecs_os_set_api_defaults()`, then `ecs_os_get_api()`, then
patch, then `ecs_os_set_api()`. Skipping the first call is not a small mistake:
`ecs_os_set_api` latches `ecs_os_api_initialized`, and `ecs_os_init` — which runs inside
`ecs_init` — installs defaults only when that latch is clear. A caller who patches the
allocator onto a freshly zeroed struct therefore ends up with null `log_`, `abort_`,
`get_time_` and every thread, mutex and condition-variable callback, and flecs calls
through one of them during world creation. The crash is a jump to address zero inside
`ecs_init`, some distance from the cause. `src/os.zig` always performs the full
sequence.

**Installing an allocator too late is silently accepted, not refused.**
`ecs_os_set_api` (`flecs.c:18686`) is a no-op once the latch is set — a late call is
ignored, and the caller is told nothing. With `FLECS_OS_API_IMPL` in the build, which is
the common case and this package's default, it is worse than that:
`ecs_os_set_api_defaults` clears the latch again on its way out, so a late call
*succeeds* and swaps the allocator while flecs holds live blocks from the previous one.
Every subsequent free of an older block goes to the wrong allocator.

flecs will not stop either case. `zecs.setAllocator` does, as an error rather than an
assert: it refuses to install once a world exists, cross-checks flecs's public
allocation counters for a world it could not have seen, and verifies after the fact that
the callbacks it installed are the ones flecs is holding.

**`ecs_os_api_malloc` asserts `size > 0` but callers are not required to honour it.**
The assert vanishes under `NDEBUG`, and `malloc(0)` is implementation-defined. The
bridge in `src/os.zig` treats a non-positive size as a failed allocation and returns
null, which is a defined answer flecs handles, rather than passing it through.

**An empty root separator silently discards the parent.** `ecs_entity_desc_t` has `sep`
and `root_sep`, and setting `sep` to `""` is the documented way to stop flecs reading a
name as a path — which matters here because Zig type names are full of dots and none of
them mean a hierarchy. Setting `root_sep` to `""` alongside it looks equally harmless and
is not: flecs decides whether a name is root-qualified with a prefix comparison against
`root_sep`, every string starts with the empty string, so every name becomes
root-qualified and `desc.parent` is thrown away. Entities come out unparented with no
error anywhere. `src/world.zig` therefore sets `sep` and leaves `root_sep` alone.

**A tag needs zero alignment as well as zero size.** `ecs_component_init` checks that
size and alignment are either both zero or both non-zero, and aborts if only one of them
is. Zig reports an alignment of 1 for an empty struct — correct for Zig, and exactly the
mismatch flecs rejects. `src/component.zig` zeroes the alignment when the size is zero.

**`FLECS_DEBUG` and `NDEBUG` together are an "invalid configuration" warning.** flecs
derives its own checking level from `NDEBUG` when told nothing, and warns when told two
things at once. Zig defines `NDEBUG` for C sources in every release mode, so asking for
checks in an optimized build would produce exactly that contradiction. `build.zig`
decides the level once and undefines `NDEBUG` when checks were asked for, which is what
makes `-Doptimize=ReleaseFast -Ddebug_checks=sanitize` a configuration that means what
it says.

### Found while binding the rest of the API

The three entries above predate full coverage. Binding every exported symbol surfaced
these, each of which a consumer would otherwise meet as a crash or a silent wrong answer.

**`ecs_world_from_json_file` returns a dangling pointer.** It reads the file into a
buffer, parses it, `ecs_os_free`s the buffer, and returns the parse position — which
points inside the block it just released. `zecs.json.worldFromJsonFile` returns `void`
for that reason.

**`ecs_iter_to_json` consumes the iterator.** It walks to the end, so flecs releases the
iterator itself. The natural Zig idiom — `var it = query.iter(); defer it.deinit();`
before the call — is therefore a double free. `zecs.json.iterToJson` marks the iterator
finished so the idiom stays correct.

**A zeroed JSON descriptor is not flecs's default, and a null one is different again.**
`ECS_ENTITY_TO_JSON_INIT` and `ECS_ITER_TO_JSON_INIT` switch several flags on that `{0}`
leaves off, while flecs's internals read a *null* descriptor as "everything on". Three
meanings for what looks like the same absence of an opinion. `zecs.json` exposes
`entity_defaults` and `iter_defaults` rather than letting `.{}` mean the wrong thing.

**`ecs_enum_init` cannot express a zero-valued constant.** It reads
`!value && !value_unsigned` as "no value was given" and auto-numbers instead, so an enum
whose zero member is not written first silently gets the wrong value. `zecs.meta` sets
the `(EcsConstant, underlying)` pair directly, which takes the value verbatim.

**`ecs_struct_init` deletes the type entity if any member fails.** On a component entity
that is destructive rather than merely a failed call. `zecs.meta` adds members one at a
time with `ecs_struct_add_member`, which also lifts the descriptor's 32-member cap.

**`EcsBitmask` is hard-wired to 32 bits** (`flecs_init_type_t(..., ecs_u32_t)`), which is
why `zecs.meta` refuses anything but a `packed struct(u32)` rather than describing it
wrongly.

**A `move` hook makes flecs destruct the source after every table change.** With `move`
null, flecs relocates with `memcpy` and leaves the source alone, which is exactly right
for Zig values — they are trivially relocatable. Supplying the hook that looks obviously
correct would free what the destination now owns. `zecs.typeHooks` therefore derives
*fewer* hooks than it appears to need, and says why.

**`ecs_os_free` is a macro, not a symbol.** Every flecs function that returns an owned
string documents freeing it with `ecs_os_free`, and there is nothing to link against —
a Zig caller holding a `?[*:0]u8` has no function to call and will reach for the host
allocator, which did not allocate it. `zecs.Str` and `zecs.strbuf.Owned` free through
`ecs_os_api.free_` instead.

**`ecs_strbuf_t` cannot be moved.** Its first 512 bytes are an array inside the struct
and `content` points into that array, so copying the struct by value after any append
leaves the copy pointing at the original's storage. `ecs_strbuf_get_small` has the same
shape: it returns interior storage for a short string and heap for a long one, so
following the header's one-line description gives either a dangling pointer or a leak.

**`ecs_get_stage`'s bounds check is `ecs_check`,** which a build without flecs's checks
compiles out; the raw call then indexes past the stage array. `World.stage` compares
against `ecs_get_stage_count` itself, so the answer does not depend on the build.

**`ecs_get_path_w_sep` returns an allocated empty string when parent and child are the
same entity,** not null. The header says "will return an empty string" and means it
literally; reading that as "nothing" leaks one allocation per call.

**`ecs_doc_get_name` falls back to `ecs_get_name`,** so it answers for almost every named
entity, and the string then belongs to the entity's name rather than to its
documentation. Setting the doc name to null returns to that fallback rather than to null.

**The alerts addon depends on the script addon and does not say so.** `flecs.h` enables
an addon's dependencies for you; `flecs.c` has one it does not declare. The alerts
implementation calls `ecs_script_vars_init`, `ecs_script_vars_from_iter` and
`ecs_script_vars_fini` (`flecs.c:24647`, `:24708`, `:24752`) outside any
`#ifdef FLECS_SCRIPT`, so `FLECS_ALERTS` without `FLECS_SCRIPT` is nine undefined symbols
at link time with nothing pointing at the cause. `build.zig` enables script when alerts is
asked for, and says so rather than doing it quietly.

Two places where the header's documentation contradicts the implementation:

- **`ecs_id_from_str`** is documented as needing `FLECS_SCRIPT`; it is compiled under
  `#ifdef FLECS_QUERY_DSL`, and `FLECS_SCRIPT` does not imply that define.
- **`ecs_get_entities`'s doxygen example** iterates the not-alive ids from
  `alive_count + 1`, skipping one. `flecs_entity_index_ids` already returns `&dense[1]`,
  so the reserved slot is gone before the pointer arrives and the correct range is
  `[alive_count, count)`.

## Archive of what was checked at this pin

- `FLECS_VERSION_MAJOR`/`MINOR`/`PATCH` are 4/1/6. The ABI guard reads them out of the
  header the library was compiled from and a test asserts them against this file, so the
  pin recorded here and the code that actually compiled cannot disagree.
- `FLECS_TERM_COUNT_MAX` is 32, `FLECS_EVENT_DESC_MAX` is 8, `FLECS_ID_DESC_MAX` is 32.
  These size public structs, so they are build options that feed both the C and the Zig
  side from one source, and the ABI guard proves the two agree.
- How many symbols this release exports, and how they split between functions and
  variables, is recorded in the two generated files rather than here.
  `src/abi_manifest.zig` is generated from the header by `zig build abi-manifest` and
  `zig build abi-manifest-check` fails if it has gone stale, which is what makes a
  re-vendor that adds API impossible to miss. `src/api_tiers.zig` is generated from
  `src/c/` by `zig build api-tiers` and re-checked by `zig build api-tiers-check`, and
  carries the counts per tier. A number copied into this file would be a second home for
  a fact that already has one, and would be stale the first time it was wrong.

## Re-vendoring procedure

`ci/verify-vendor.sh` fetches the pinned commit and compares it against `libs/`, so the
claim that this copy is unmodified is checked rather than asserted. It runs as its own
CI job. Run it after any step below.

1. Clone upstream at the new tag; copy `distr/flecs.c`, `distr/flecs.h` and `LICENSE`
   over `libs/flecs/`. Nothing else, and nothing edited.
2. Update the table at the top of this file and the pin in `ci/verify-vendor.sh`.
3. `zig build abi-manifest` to regenerate the export list, then `zig build test`. The
   ABI guard fails if any struct the Zig side mirrors has changed shape, if a signature
   moved, or if the release added a symbol nothing binds; the version assertions fail if
   step 2 was forgotten.
4. Re-read the "Upstream behaviour this package works around" section above and check
   whether any of it is now fixed. If it is, delete the workaround, not just the note.
5. Check the README's addon list against upstream's, in case the release added one.
